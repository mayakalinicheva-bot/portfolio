# portfolio — рабочее пространство Discovery

Прототип для ведения продуктового Discovery: текстовые документы, гипотезы, исследования, решения, сущности, задачи, матрица требований, CRUD по ролям и основной отчёт.

## Локальный запуск с сохранением на диск

Из корня репозитория:

```bash
python3 05-training-frontend/server.py --port 8000
```

Откройте `http://127.0.0.1:8000`. Сервер использует только стандартную библиотеку Python 3.9+. Он записывает рабочее пространство в `05-training-frontend/workspace/discovery.json`, предыдущую версию — в `workspace/discovery.previous.json`, основной отчёт — в `reports/discovery-report.md`. Запись атомарная, конфликт двух открытых вкладок не перезаписывается молча. Браузер хранит отдельную аварийную копию и предлагает восстановить её после сбоя.

## Что есть в интерфейсе

- **Документы:** 17 исходных Markdown-материалов проекта, включая полную рабочую рамку Project Scope, заметки о решениях, аудит сайта и материалы Behance. Их можно редактировать, просматривать в Markdown и дополнять новыми документами по шаблонам (Project Scope, теория продукта, JTBD, план интервью, метрики).
- **Гипотезы, исследования, решения:** отдельные записи со статусом, формулировкой, способом проверки, свидетельствами и выводом.
- **Сущности и матрица:** предложенные группы сущностей, связанные блоки и 48 строк исходной рабочей матрицы. Можно добавлять новые строки, править поля и связывать материалы.
- **CRUD:** отдельные права по роли, владельцу и состоянию объекта; «не решено» отличается от запрета.
- **План и основной отчёт:** задачи Discovery и выбранные материалы. Кнопка «В основной отчёт» на карточке добавляет текущую версию материала. Отчёт сохраняется как Markdown и доступен для скачивания.
- **Поиск, навигация и архив:** глобальный поиск через `⌘ K` / `Ctrl+K`, кнопка «Назад», хлебные крошки и восстановление записей из архива.
- **ChatGPT и облако:** защищённая синхронизация между устройствами через Private Vercel Blob и входящие структурированные предложения из [личного Plugin](PLUGIN-SETUP.md).

Исходные `.md` и `.xlsx` не перезаписываются: интерфейс редактирует рабочую копию с указанием её источника. Все записи и статус решений остаются черновыми, пока пользователь не изменит их явно.

## Размещение на Vercel

Vercel: импортировать репозиторий `mayakalinicheva-bot/portfolio`, выбрать **Root Directory** `05-training-frontend`, **Framework Preset** `Other`, **Production Branch** `main`. Файл `vercel.json` задаёт `public` как выходную папку. Обновить статические файлы можно командой:

```bash
python3 05-training-frontend/build_public.py
```

На Vercel публикуется сайт и API для закрытой синхронизации. Пока Private Blob и ключ не настроены, правки сохраняются в браузере каждого устройства отдельно. После подключения облака по инструкции из [PLUGIN-SETUP.md](PLUGIN-SETUP.md) сайт сохраняет одну общую рабочую копию; Plugin читает её через MCP и отправляет предложения во входящие. Можно перенести рабочую копию через «Резервная копия» → «Импортировать». Локальный сервер сохраняет изменения на диск и не доступен через публичный сайт. GitHub не получает редактируемые записи автоматически.

Публичная папка `public` не содержит локальный файл `workspace/discovery.json` и резервные копии. Исходные материалы импортируются в демонстрационную копию нового браузера; перед публикацией проекта проверьте, какие документы готовы быть общедоступными.
