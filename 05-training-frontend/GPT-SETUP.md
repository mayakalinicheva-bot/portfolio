# Проектный GPT для portfolio Discovery

> Для личного аккаунта ChatGPT создание новых GPT недоступно. Актуальная настройка — [личный Plugin и MCP](PLUGIN-SETUP.md). Эта инструкция сохранена для рабочих пространств, где GPT Actions ещё поддерживаются.

Публичный сайт: <https://portfolio-discovery.vercel.app/>. Рабочая копия хранится в **закрытом** Vercel Blob. Обычная история чатов ChatGPT не передаётся приложению автоматически. Этот мост работает только в отдельном проектном GPT, когда он вызывает свои Actions.

## Настройка владельцем

1. В Vercel откройте проект `portfolio-discovery`, создайте **Private Blob** store и подключите его к Production.
2. Добавьте в Production Environment Variable `DISCOVERY_SYNC_KEY` — длинный случайный секрет. Значение не добавляйте в GitHub и не отправляйте в чат. После изменения переменных сделайте Redeploy.
3. На сайте откройте **GPT и облако → Подключить облако**, введите тот же ключ. Существующая рабочая копия в браузере перед подключением скачивается резервной копией. Если облако пустое, текущая копия загружается туда.
4. В ChatGPT создайте отдельный GPT для проекта, добавьте Action из [gpt-action.yaml](gpt-action.yaml), выберите API Key / Bearer и введите `DISCOVERY_SYNC_KEY` в интерфейсе настройки действия. Не включайте публичную публикацию GPT с внутренними материалами.
5. Скопируйте инструкции ниже в поле Instructions и протестируйте в Preview: вызов `getDiscoveryContext`, затем пробное `submitDiscoveryProposal`. Предложение должно появиться в разделе **GPT и облако** на сайте.

### Инструкции для GPT

> Ты — партнёр по продуктовому Discovery проекта portfolio. В начале обсуждения проекта вызови `getDiscoveryContext`, чтобы опираться на актуальный Project Scope, сущности, требования и статусы. Различай факты, гипотезы, предложения и принятые решения. Не превращай гипотезу в подтверждённое решение без явного основания.
>
> По мере обсуждения выделяй только выводы, которые стоит сохранить: новую гипотезу, наблюдение исследования, предложение решения, сущность, требование, задачу или документ. Не отправляй каждую реплику, личные данные участников, длинный сырой транскрипт или повтор существующего пункта. Для каждого содержательного вывода вызови `submitDiscoveryProposal` с типом, понятным заголовком, формулировкой, названием чата как `sourceChat` и кратким основанием как `basis`. Если материал относится к существующей записи, укажи её `targetRef`. Не вызывай действие, если вывод ещё слишком неопределённый.
>
> После отправки сообщи, что предложение находится на проверке в песочнице. Только владелец переносит его в рабочие материалы кнопкой «Добавить в Discovery». Перед новым обсуждением снова читай контекст. Если действие недоступно или вернуло ошибку, скажи об этом прямо и не утверждай, что запись сохранилась.

## Как работает двусторонний обмен

- **Сайт → GPT:** Action `getDiscoveryContext` читает актуальную облачную рабочую копию. GPT получает текст Project Scope, списки документов, гипотез, решений, сущностей и требований.
- **GPT → сайт:** Action `submitDiscoveryProposal` записывает отдельный структурированный кандидат во входящие. Владелец просматривает и добавляет его в Discovery или отклоняет.
- **Между устройствами:** после ввода ключа сайт загружает и сохраняет одну облачную копию. При конфликте двух вкладок изменения не перезаписываются молча; скачайте локальную копию и обновите облако.

Ключ даёт доступ к рабочим материалам. Храните его только в Vercel, настройках GPT и на личных устройствах. На сайте флажок «Запомнить ключ» выключен по умолчанию; без него ключ живёт только в сессии браузера.
